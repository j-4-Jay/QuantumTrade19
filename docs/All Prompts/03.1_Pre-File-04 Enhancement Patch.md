## Non-Negotiable Data Rules

1. **CoinDCX Futures only. Never Spot.**
   - All candles, current prices, historical data, POI calculations, chart labels, positions, risk data, and Deep Historical Data operations must use CoinDCX Futures endpoints/data paths only.
   - Never call or render CoinDCX spot candles.
   - Existing validated Futures pair format such as `B-BTC_USDT` remains the source identity.

2. **Exchange math stays UTC-correct.**
   - Candle storage, period boundaries, PDH/PDL, 4H H/L, 1W, 1M, aggregation, POI calculations, source candle indices, and strategy decisions use validated CoinDCX Futures UTC boundaries.
   - Do NOT recompute POIs on NY day/session boundaries.
   - This is already proven by real Futures validation:
     - PDH = 63595.1
     - PDL = 62484.2
     - Previous 4H High = 63097.3
     - Previous 4H Low = 63011.6

3. **Display time is America/New_York only.**
   - Convert broker/UTC timestamps to `America/New_York` automatically with DST.
   - User-visible date format:
     `DD-MM-YYYY <Weekday>`
   - User-visible time format:
     `hh:mm AM/PM`
   - Tooltips must show both NY display time and UTC broker source time when source-period interpretation matters.

4. **UI never directly calls CoinDCX.**
   - Trading Panel consumes Monitor interfaces only:
     - `MarketDataMonitor.get_historical_candles(symbol, tf, days)`
     - `MarketDataMonitor.get_live_candle(symbol, tf)`
     - `MarketDataMonitor.get_health()`
     - `POIMonitor.get_active_pois(symbol)`
     - `POIMonitor.get_poi_state(symbol, poi_id)`

# Scope F — Deep Historical Data Card Upgrade

Follow the approved Deep Historical Data visual reference.

For every symbol and each timeframe where historical days can be entered/displayed, show:

```text
Available in QT19 Database: A Days
Available in Broker Database: B Days
```

Definitions:
- A = actual local historical coverage, persisted and calculated from manifests/database.
- B = broker historical ceiling, persisted from HistoryDepthProberWorker.

Per-symbol controls:

```text
Download More: [ N ] Days

[ Start Download ] [ Cancel ]

[ Recycle / Clear Local Archive ]
```

Rules:
- N means additional older days beyond current local coverage.
- Download fills missing historical range backward while live data continues accumulating toward current time.
- Deep history never competes with live data/API calls.
- Cancel stops future chunks and preserves downloaded data.
- Clear requires confirmation.
- Clear removes deep/archive historical data for that symbol only.
- Clear does not remove the mandatory five-day 1m/5m/15m baseline; re-download baseline if needed.
- Start/Cancel/Clear states must be visual and animated, not text-only.
- Show progress, coverage date range, local days, broker days, queue/downloading/paused/complete/error state.
- Persist progress across restart.
