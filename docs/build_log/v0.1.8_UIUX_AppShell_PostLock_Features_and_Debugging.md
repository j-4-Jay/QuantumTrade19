## 2. Real bugs found and fixed (chronological, this round)

1. **Splash performance/warning bug (the big one)**: the original splash loop woke up 60 times over 6s, broadcasting a state delta every 0.1s. Multiple orphaned copies (from page refreshes) competed for Reflex's single-threaded event loop, causing ~10s of unresponsiveness on ANY click and the "disconnected client" console spam. Fixed by making the bar's visual animation pure client-side CSS/JS and the backend do exactly one operation per splash run.
2. **`on_load()` screen-hijack**: was pulling `screen` from the shared engine singleton's last-known value on every page refresh, skipping the splash animation entirely. Removed; splash always plays fully now.
3. **Splash freezing on second appearance (post-logout)**: the bar-fill script was a static embedded `<script>` tag, which reliably runs on the very first load but browsers don't guarantee re-executing identical script content a second time. Fixed by triggering the animation via `rx.call_script` from the Python handler, guaranteed fresh every mount.
4. **Stale computed vars**: `totp_required`, `forgot_available_methods`, `forgot_has_any_method` were `@rx.var` reading untracked external state, so Reflex computed them once and froze them for the session (explains: TOTP box never appearing after registering, Manage Security showing stale Enable/Disable status, Forgot Password showing zero methods). Converted to plain fields, explicitly refreshed at every relevant transition.
5. **`AttributeError` crashes (x2)**: `SecurityMonitor`/`MasterAppEngine` on disk were stale pre-Telegram/Discord versions missing several methods the current `app_state.py` called. Resupplied both files in full.
6. **Cursor invisible, then vanishing**: (a) a transform-math bug where the base position (-9999px) was never reset, so `translate3d` offsets stayed permanently off-screen; (b) an early `if (!halo || !img) return` bail-out that silently aborted the whole setup if elements weren't in the DOM at the exact microsecond the script ran. Ultimately the whole feature was removed per request instead of continuing to chase it.
7. **Login card "shining" instead of "light balls moving"**: an early conic-gradient border technique read as one diffuse wedge. Replaced (with the user's own superior CSS Motion Path file) - the only remaining defect was a missing `@keyframes qt19-border-chase-move` block, which is why the dot was visible but frozen.
8. **Browser autofill invisible to the app**: Chrome/Edge autofill sets input values directly at the browser level without firing the event React's `onChange` listens for - fields looked filled but `AppState` genuinely had empty strings. Fixed via the standard `:-webkit-autofill` animation-hook detection + forced synthetic `input` event dispatch.
9. **Manage-Security button rendering outside the card**: `width="100%"` on two sibling buttons in the same row made each claim the full row width and overflow sideways. Fixed with `flex="1"`.
10. **Logo never rendering**: the app never actually had a real `logo.png` file (earlier "working" screenshots were the user's design mockups, not app screenshots) - the request was silently served the SPA's fallback HTML (misleading 200 status, `Content-Type: text/html`). Replaced with a self-contained CSS/icon-based mark requiring zero external file.
11. **Recurring post-splash delay (~15s -> ~5s -> [pending]))**: three layers diagnosed and fixed in sequence -
    - `keyring`'s first-ever backend auto-detection in a fresh process (multi-second, well-documented) - fixed with a warm-up call at construction time.
    - Every credential/settings check re-reading from the real OS keychain / disk on every transition, with no caching - fixed with in-memory caching in `SecureKeyStorageWorker` and `SettingsPersistenceWorker`.
    - **[UNCONFIRMED]** React Strict Mode (confirmed active via a browser console warning) double-invokes mount effects in dev mode; `on_mount=AppState.run_splash_sequence` likely fires twice per mount, so a duplicate 5s+2s wait was still occupying the session's event queue behind the scenes even after the screen had visually moved to Login. Fixed with a `_splash_task_running` guard flag that makes the second invocation exit immediately. **This fix has not yet been retested by the user as of pausing this session.**
