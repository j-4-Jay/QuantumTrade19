## 1. What Module 01 delivers

QuantumTrade19's entire app-shell lifecycle, branding, theming, and account-security system, built
as a Reflex (Python → Next.js/Vite) desktop-style web app:

**Screen lifecycle:** Splash → Register (first run only) / Login → Dashboard shell, with Manage
Account Security, Forgot Password, and App Lock as reachable sub-screens, and Logout cycling back
through Splash → Login.

## 2. Worker Engines

### Security Monitor
| Worker | Responsibility |
|---|---|
| `Secure_KeyStorage_Worker` | OS-keychain-backed secret storage via `keyring`, with a startup warm-up call and an in-memory read cache (each key read from the real OS store at most once per server run) |
| `Auth_Login_Worker` | Salted-hash username/password set/verify; rejects blank/short input |
| `TOTP_2FA_Worker` | Real Google-Authenticator-compatible TOTP via `pyotp`; QR generation via `qrcode` |
| `App_Lock_Worker` | Manual + inactivity-timeout UI lock; never touches background engines |
| `OTP_Delivery_Worker` | Generates short-lived OTPs; delivers via Telegram Bot API / Discord webhook; test-sends return `(success, detail)` with the exact failure reason |

### UI Experience Monitor
| Worker | Responsibility |
|---|---|
| `Theme_Engine_Worker` | Resolves/selects/persists the 6 locked themes (Yellow/Saffron/Blue × Day/Night) |
| `Sound_Engine_Worker` | Master + per-event UI sound-effect toggles |
| `Cursor_Glow_Worker` / `Animation_Choreographer_Worker` / `Page_Transition_Worker` | Present in the architecture; the custom-cursor feature they originally supported was built and then fully removed per explicit request - the app uses the plain OS cursor |

`Settings_Persistence_Worker` backs non-secret settings (`data/settings.json`) with the same
read-once-per-run in-memory caching pattern as the keystore worker.

## 3. Monitor & Master Engines

- `SecurityMonitor` — sequences all Security Workers; owns registration, login, lock/unlock, TOTP
  enable/disable, Telegram/Discord config + test, and the Forgot-Password identity-verification logic.
- `UIExperienceMonitor` — sequences the UI Experience Workers; theme CSS vars, sound toggles.
- `MasterAppEngine` — owns the full screen enum (`SPLASH`, `REGISTER`, `LOGIN`, `MANAGE_SECURITY`,
  `FORGOT_PASSWORD`, `SHELL`, `LOCKED`) and every transition between them. Imports only the two
  Monitors, never a Worker directly.

## 4. UI, screen by screen (final behavior)

| Screen | Final behavior |
|---|---|
| **Splash** | Bar fills over 5s (pure CSS/JS, zero backend chatter during the fill), holds 2s at 100%, then a hardcoded dissolve (never the random effect pool) into Register/Login |
| **Register** | Username/password + optional Google Authenticator opt-in (QR + confirm code); "Back to Login" button; no recovery-code step (removed by design) |
| **Login** | Username/password, TOTP field only when actually enabled; "Submit" pill button pulses crimson while typed credentials don't match what's on file (checked live, every keystroke, locally) and lime green the instant they do - glow-only, no button scaling, slow/subtle/30%-transparent per final tuning; links to Forgot Password and Manage Account Security; traveling light-ball comet effect on the card border |
| **Manage Account Security** | Password-gated; enable/disable/re-enroll TOTP; configure + test Telegram bot and Discord webhook with inline setup instructions and "Configured" status badges |
| **Forgot Password** | Offers whichever of TOTP/Telegram/Discord are active; sends a real OTP via the chosen channel; resets directly with zero verification if none are configured (explicit, accepted tradeoff for this offline single-user app); Cancel button on the reset stage |
| **App Lock** | Freezes only the UI; background engines keep running; TOTP field conditional on enrollment |
| **Dashboard shell** | 5 locked sidebar tabs; theme picker as a dropdown; Paper/Live toggle with fixed width and a distinct red "LIVE" vs. theme-accent "PAPER" glow; working sound-mute toggle; single Lock control; Logout button with an open-trades confirmation dialog (stubbed pending the future Execution Monitor); table header/cell text explicitly theme-bound so it stays readable on light Day themes |
| **Global** | Keyboard shortcuts (Enter submits, Escape backs out/cancels) via a simple per-screen ID convention; 10 configurable page-transition effects (dissolve, zoom in/out, 4× slide, 2× flip, blur-in) applied to every screen change, chosen via Settings (single/sequential/shuffle mode); browser-autofill values are correctly synced into app state (Chrome/Edge autofill bypasses React's normal change detection otherwise) |

## 5. Significant bugs found and fixed (full history, consolidated)

1. Reflex app package folder nesting requirement.
2. Test isolation from the real OS credential store (`force_memory` pattern).
3. `rx.foreach` + plain-dict-indexed-by-Var → fixed with `rx.match`.
4. `rx.foreach` on untyped `-> list` computed vars → fixed with concrete generic type hints.
5. `on_change` handler parameter naming (`v` → `value`, matching Reflex's dispatch convention).
6. Blank-credential login/registration bypass.
7. Splash progress bar reliability → `rx.progress`, then later a fully custom CSS/JS bar.
8. Stale `@rx.var` computed properties (TOTP status, Forgot Password method list) frozen for the
   session → converted to plain fields, explicitly refreshed at every relevant transition.
9. `on_load()` silently skipping the splash animation on refresh by pulling stale screen state from
   a shared engine singleton → removed; splash always plays in full now.
10. Splash freezing on its second appearance (post-logout) → static embedded `<script>` doesn't
    reliably re-execute on a second identical mount; fixed via `rx.call_script` fired from Python.
11. Two separate `AttributeError` crashes from stale `SecurityMonitor`/`MasterAppEngine` files on
    disk missing Telegram/Discord methods → both fully resupplied.
12. Custom cursor: transform-math bug (permanent off-screen offset), then a silent setup-abort race
    condition → ultimately the whole feature removed per request in favor of the plain OS cursor.
13. Border-light effect rendering as a diffuse "shine" instead of moving lights → replaced with a
    CSS Motion Path (`offset-path`/`offset-distance`) technique; the one remaining bug (a missing
    `@keyframes` block) was found and fixed.
14. Browser autofill invisible to the app (Chrome/Edge sets input values without firing the event
    React listens for) → fixed via the standard `:-webkit-autofill` detection-hook + forced
    synthetic `input` event.
15. Manage-Security buttons overflowing outside the card (`width="100%"` on sibling buttons in the
    same row) → fixed with `flex="1"`.
16. Logo never rendering → the app never had a real `logo.png` file (earlier "working" screenshots
    were design mockups, not the app) → replaced with a self-contained CSS/icon mark, zero file
    dependency.
17. Recurring post-splash unresponsiveness, addressed in three layers: `keyring`'s one-time backend
    auto-detection cost (fixed with a startup warm-up call), repeated uncached keychain/disk reads on
    every transition (fixed with in-memory caching), and React Strict Mode's development-mode
    double-invocation of mount effects likely starting a duplicate splash timer every mount (fixed
    with a `_splash_task_running` guard flag).

## 6. Known open defect at lock time

**The Login-screen response delay is not fully confirmed fixed.** Three real, independent
contributing causes were found and fixed in sequence (keyring cold-start, uncached repeated
reads, and a suspected Strict-Mode duplicate task) - delay dropped from ~15s to ~5s across these
fixes, and the final guard-flag fix has been applied but not yet retested end-to-end by the user
before this lock. If it resurfaces, the recommended next diagnostic is to confirm whether the delay
duration tracks `SPLASH_DURATION_SECONDS`/`SPLASH_HOLD_SECONDS` exactly (proving something is still
tied to the splash timer) or is fixed regardless of those values (pointing elsewhere entirely).

## 7. Deliberately deferred (not defects)
