## Delivered Architecture

Tier 2 `SetupDetectionMonitor` (`engines/monitors/setup_detection_monitor.py`) wires 7 Tier 1 Workers behind the locked interface:

```python

get_confirmed_setups(symbol, tf)

```

Delivered Workers:

1. `CandleColorClassifierWorker` — Green/Red from close-vs-open only, doji → `None`.
2. `POIInteractionDetectorWorker` — Touch/Sweep/Cross per closed candle vs every active POI; Scenario-B retest/double-cross-flip read directly off File 03's `POIStateRecord.state` and `INVERSE_FVG` role — zero re-derivation.
3. `Bull123FSMWorker` / `Bear123FSMWorker` — the Candle1/2/3 role-assignment machine, independently per (symbol, timeframe, poi_id), sharing a `CandleLockRegistry` so no candle is ever reused across setups, directions, or POIs.
4. `EngulfingDetectorWorker` — Candle2-fully-engulfs-Candle1 confidence input.
5. `FVGConfirmationDetectorWorker` — Candle3/Candle1 FVG confidence input.
6. `MTFCascadeWorker` — 15m/5m → 1m cascade: timeout, proximity guard, HTF-extreme break, tighten-to-1m-SL on success, hard "no trade" on any cancellation.

## Algorithm — final, validated form

The Candle1/2/3 machine (`_fsm_base.py`) is **color-agnostic at the anchor/pairing stage** — direction is decided only at the confirmation test (Candle2/Candle3 color + extreme check), matching the master prompts' own description of Bull/Bear as mirror images of one shared mechanic. States per (symbol, timeframe, poi_id): `NONE → ANCHOR → WAITING_C3 → confirmed/aborted`.

Two real bugs were found and fixed via the check gate (see `_fsm_base.py` header for full detail):
1. Candle1 is not color-locked per direction (a Green candle can anchor a Bull-flavored search).
2. On a failed Candle3 test, the engine recycles **Candle2** (not the failing candle) as the new Candle1, and immediately re-tests the failing candle as the new Candle2.
