# FT-H.39 popup UX addendum v0.2.0
Jay requested 08-11-2026. Supplements original spec and highlight addendum. Pending local testing and Jay confirmation; not locked.
Middle-button press on popup closes it; X remains; outside click does not close. Prevent browser middle-button autoscroll on popup. Drag handle uses open-hand hover and grabbing during drag; resize uses diagonal arrow throughout interaction; pointer-up/cancel, window blur, close and detach clean up temporary cursors.
Minimum size is 280x248, prioritizing heading, NY/IST time and five OHLCV rows. At minimum height compact view hides footer controls, comparison subrows and badge, not OHLCV. X remains available. A scrollbar protects readability where text is unusually long. Manual enlargement restores full content. Double-click bottom-right grip first restores creation size 304x286, second selects compact minimum, then alternates. Position clamps into chart when toggling. No data or per-popup refresh state is discarded by compact view.
Locator notes use chart scroll/zoom/range/pane actions and a coalesced one-frame callback only while the note is active. Returning candle visibility restores the prior note, but never overwrites newer unrelated DB/Compare text. Unsubscribe on resolution/close/detach; no additional polling. No automatic chart movement or extra data reads.
DB read errors are explicitly labeled as errors; absent rows are separate. Live fallback requires a genuinely forming last candle in the original timeframe. Baseline persistence repair verification: Jay reported 480 passed/23 skipped and zero missing rows in nine last-three-day checks; subsequently reported popup database behaviour satisfactory. This does not certify all older history or equality with exchange.
Acceptance checks: middle click and X close; outside click stays; grab and resize cursors correct and restore after release; minimum shows title/both times/all OHLCV; first double-click default/second compact; refresh preserves compact layout; scroll candle out and back clears only locator note; buttons and highlight still work; no extra idle CPU. Confirm in actual application before lock.
