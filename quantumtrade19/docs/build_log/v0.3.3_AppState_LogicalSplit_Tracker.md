## Script behavior

The script checks the exact approved source hash before changing anything:

```text
C0184C1A9715C790441F8650F06BF1EFBA18BE0BD17CF893C528B9981C6DF69A
```

If the hash differs, it stops without modifying files.

When the hash matches, it:

1. Creates a timestamped original backup in `state/backups/`.
2. Creates `state/app_state_parts/`.
3. Writes five logically grouped source snapshots:
   - `01_core_shell.py`
   - `02_auth_security.py`
   - `03_market_dashboard.py`
   - `04_poi_settings.py`
   - `05_trading_panel.py`
4. Runs `python -m py_compile state/app_state.py`.
5. Restores the backup automatically if Python compilation fails.

## Important current boundary

This first script is intentionally **non-invasive**: it creates and validates the five logical source files while the app continues to execute the existing `state/app_state.py`. It does not yet import or execute methods from the five files. Making them executable requires a proper mixin architecture and a full integration check; that is the next refactor step.

## Check gate

After running the script:

1. Confirm the script prints `SUCCESS`.
2. Confirm a backup exists in `state/backups/`.
3. Confirm the five files exist in `state/app_state_parts/`.
4. Start the app and confirm login, Dashboard, Settings, POI controls, and Trading Panel still load.

## Current Trading Panel finding

The chart’s viewport reset occurs because `poll_trading_panel_chart()` calls `refresh_trading_panel_chart()` every 3 seconds, and that assigns a new complete `trading_panel_candles` list. The installed `react-klinecharts` package documents that replacing the static `data` list re-applies chart data; streaming should use `dataLoader` for live updates. [web:177]

## Next step after check

Create a real executable AppState mixin architecture, then implement Trading Panel viewport preservation with an OHLC-only polling path and deliberate Follow Live / Go to Live behavior.
