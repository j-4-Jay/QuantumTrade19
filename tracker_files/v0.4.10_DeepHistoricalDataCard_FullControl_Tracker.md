## 1. Why This Was Built

User approved the v0.4.9g card mockup and requested 4 additional controls:

1. Per-symbol Download Duration input (Days/Months/Years) that downloads
   1m + 5m + 15m together in chunks with a progress bar, independent of
   live candle fetch/render.
2. Startup auto-scan: detect existing TF gaps and fetch the broker ceiling
   automatically at app launch, so the ceiling becomes the user's reference
   without any manual click.
3. Auto-heal red gap markers at startup, with a manual per-bar click as a
   fallback.
4. Bar should represent % of DB-present relative to the actual broker
   ceiling, not an arbitrary max().

### deep_history_card_mixin.py
- `set_card_duration_value` / `set_card_duration_unit` / `download_card_duration`:
  per-symbol duration input state and the Download action, converting
  Days/Months/Years to a day count and calling
  `engine.market_data.start_deep_history(symbol, tf, days)` for 1m, 5m, 15m
  together via the existing DeepHistoryDownloaderWorker - completely
  separate from CandleBuilderWorker's live in-memory series and the 0.5s
  live poll, so it cannot interfere with live rendering.
- `startup_scan_deep_history_background`: new background event, guarded by
  `_deep_history_startup_scanning`. For every active symbol and every TF it
  fires a broker depth probe (network, non-blocking) and calls
  `_heal_existing_gap`.
- `_heal_existing_gap` / `heal_tf_gap`: bounded auto-heal. Only triggers a
  download when a TF already has 2+ physical SQLite ranges (a real internal
  gap). The target range is bounded to the existing earliest-to-latest
  span for that TF, so it closes existing holes without silently starting
  an unbounded new download the user never requested. `heal_tf_gap` exposes
  the same logic for manual per-bar clicks.
- `green_pct` calculation changed: uses `db_days / broker_days` once a
  ceiling is known, falling back to the old `max(db_days, 1)` formula only
  while the ceiling is still "Not probed".
- `deep_history_symbol_cards` now also computes `combined_percent` and
  `combined_active` per symbol, aggregating all three TFs'
  present/required candle counts from `DeepHistoryDownloaderWorker.get_status`.

### core_shell_mixin.py
- `on_load` now returns
  `[type(self).start_poi_monitor_background, type(self).startup_scan_deep_history_background]`
  instead of just the POI monitor trigger, so the new startup scan runs
  automatically on every app launch. No other behavior changed.

### app_state.py
- Added `deep_history_card_duration_value: dict[str, str]`,
  `deep_history_card_duration_unit: dict[str, str]`, and
  `_deep_history_startup_scanning: bool` fields. No existing field removed.

### deep_historical_data_card.py
- Added the Download Duration control (input + unit select + Download
  button) to each card header.
- Added a combined per-card progress bar, shown only while any of that
  symbol's three TFs is actively downloading.
- Mini bars are now clickable (`on_click=AppState.heal_tf_gap(...)`) to
  manually heal a gap.
- A small red dot now appears next to a TF label when that TF has a
  detected gap, in addition to the red segment inside the bar itself.
- A white 2px marker line is drawn at the right edge of the bar once a
  broker ceiling has been probed, since the bar is now scaled to that
  ceiling as its 100% reference.

## 3. Data Integrity Preserved

- Broker ceiling probing still never calls `HistoryManifestWorker.mark_covered`
  and never touches SQLite - `start_ceiling_probe` is unchanged from v0.4.8.
- Auto-heal only ever bounds itself to a TF's OWN existing earliest-to-
  latest span - it cannot expand a symbol's local footprint beyond what a
  human already started downloading via the Trading Panel or the new
  Download Duration control.
- The manual Download Duration control uses the same
  `DeepHistoryDownloaderWorker.start_download` path as the Trading Panel's
  Display Days box, so it inherits the same persist-first-then-manifest,
  SQLite-truth, and broker-ceiling-reported-separately guarantees already
  locked in v0.4.8.

   broker_days once a ceiling is known (spot-check one symbol/TF against
   a direct SQLite row count and the probed ceiling value).
