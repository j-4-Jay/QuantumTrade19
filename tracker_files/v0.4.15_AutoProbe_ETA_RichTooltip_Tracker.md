## 6. Proposed v0.4.16 Scope - True Push-Based Live Sync (Not Built Yet)

Root cause of any remaining perceptible delay: the Trading Panel currently
POLLS for the latest candle every 0.5 seconds and pushes it - ticks are
processed by CandleBuilderWorker the instant they arrive over the
WebSocket, but the BROWSER only learns about it on the next poll tick, so
worst-case UI-visible latency is bounded by the poll interval, not the
network.

Proposed fix for a future dedicated patch:
- Add a real callback hook to CandleBuilderWorker fired synchronously the
  moment a live tick updates the current forming candle (not just on
  candle close).
- Have MarketDataMonitor register a per-connection dispatch callback that
  the Reflex background task can `await` on (e.g. via an asyncio.Queue or
  Condition) instead of sleeping a fixed interval.
- Replace `poll_trading_panel_chart`'s fixed `asyncio.sleep(0.5)` loop with
  an event-driven wait, so a new tick is pushed to the browser within
  milliseconds of arriving over the WebSocket, not up to 500ms later.
- This is a genuine core-engine change (CandleBuilderWorker + WSFeedWorker
  callback chain) and should be scoped, built, and validated as its own
  tracker (v0.4.16) with full regression testing against File 02/03, rather
  than rushed into this patch.
