## 1. Problems Reported

1. The hover-card tooltip was not appearing at all.
2. The ETA was not showing anywhere - no visual indication that a
   download/heal was happening in the background at all ("user seems
   blind").
3. The Probe button should be removed since probing is fully automatic.

## 2. Root Causes Found

### Tooltip invisible
Radix's `HoverCardContent` renders inside a **portal** - real DOM elements
appended near `<body>`, outside this component's own subtree. CSS custom
properties (`var(--qt19-glass-bg)`, `var(--qt19-text-primary)`, etc.) only
cascade to actual DOM descendants of wherever they are defined. A portaled
element does not inherit variables scoped to a card elsewhere in the tree,
so the hover card rendered with a transparent background and invisible
text - technically present, but completely unreadable.

### ETA invisible
Two combined bugs:
- `eta_label` rendered as an empty string until the downloader had
  collected a second rate sample, so a freshly-started download showed
  nothing for the first tick or more.
- There was no animated indicator at all - only static text that could be
  trivially missed even once populated.

## 3. Fixes Applied

### ui/components/deep_historical_data_card.py
- All colors used inside the hover-card content (`_hover_card_content`)
  and the `rx.hover_card.content(...)` style are now **hardcoded hex/rgba
  values** (`_CARD_BG`, `_CARD_BORDER`, `_TEXT_PRIMARY`, `_TEXT_MUTED`,
  `_GREEN`, `_BLUE`, `_RED`) instead of `var(--qt19-*)` references, so the
  card is visible regardless of where Radix portals it in the DOM.
- Added `rx.spinner` (a standard, already-animated Reflex/Radix component -
  no custom CSS/keyframes needed) next to the ETA text both in the mini
  bar itself and inside the hover-card content, and next to the combined
  per-symbol progress bar, whenever a TF or symbol is actively
  downloading/healing.
- Removed the "Probe" button entirely from the card header.

### state/app_state_mixins/deep_history_card_mixin.py
- `_fmt_eta(None)` now returns `"Estimating..."` instead of an empty
  string, so busy state ALWAYS shows visible text immediately, even before
  a real rate sample exists.
- Removed `probe_symbol_ceiling` from active UI wiring (broker ceiling
  probing remains fully automatic via the backend `GapAutoHealWorker`
  engine from v0.4.15 - unchanged).
