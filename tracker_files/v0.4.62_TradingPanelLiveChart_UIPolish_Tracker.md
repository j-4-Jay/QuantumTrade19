## 2. Confirmed, Locked Fixes (this session)

### Backend / data integrity
- **Gold (B-XAU_USDT) never downloaded historical data.** Confirmed via
  direct broker HTTP test: the broker's candles REST endpoint uses
  `B-XAUT_USDT` for Gold, not `B-XAU_USDT` (a broker-side naming
  divergence between the live WS feed and REST history). Fixed via a new
  `engines/workers/market_data/broker_symbol_map.py` translation layer,
  applied only to outgoing HTTP requests — the internal symbol name is
  unchanged everywhere else (SQLite, UI, WS).
- **Deep Historical Data card showed "0.003 days" despite large real
  archives.** Root cause: the card read `covered_days` (newest *unbroken*
  chunk only) instead of summing ALL physically stored ranges. Fixed to
  use `candle_store.get_physical_ranges()` consistently for both the
  mini-bar label and the confirm-dialog check.
- **Delete Data left the progress bar stuck at 100%/complete.** Root
  cause: `DeepHistoryDownloaderWorker` cached its last-known status
  forever; delete never invalidated it. Added `reset_status()`, called by
  `market_data_monitor.delete_deep_history()`.
- **Infinite re-download loop on an unreachable historical gap (BTC 1m,
  ~327-day gap).** Confirmed via direct broker HTTP tests: the broker
  returns the same single boundary candle forever for that range — a
  genuine, permanent broker-side retention limit. Fixed by detecting
  "zero backward progress" and treating it like an empty response
  (`broker_ceiling_reached`), stopping the retry loop cleanly.
- **History depth prober timing out under real load.** Confirmed via
  running-app error logs (`ReadTimeoutError` at the old 10s boundary while
  a 15s standalone test succeeded). Raised timeout to 20s + added 2
  retries with backoff.

### Frontend / state wiring (extensive drift-repair across the session)
- Fixed multiple `state/app_state.py` / mixin field mismatches
  (`engine`/`_engine` alias collision, `ComputedVarShadowsBaseVarsError`,
  missing `trading_panel_tf_progress`, missing `deep_history_card_mixin.py`
  entirely, `SymbolRegistryWorker.get_symbols` → `get_symbols_sorted`,
  `SettingsPersistenceWorker.save()` single-dict signature).
- `active_tab` and `settings_active_subtab` now correctly persist and
  restore across restarts (previously never saved).
- Background pollers (`poll_trading_panel_chart`, `poll_deep_history_cards`)
  now correctly auto-start in `on_load()` when landing directly on a tab,
  not only when switching to it manually.

### Trading Panel — THE live price line fix (multi-stage root cause)
Confirmed via live browser DevTools console capture, in order of
discovery:
1. **klinecharts v10.0.2 removed `updateData()`/`applyNewData()` entirely**
   (confirmed against the library's own official v9→v10 migration guide).
   Rewired the whole live-update path to v10's real API:
   `chart.setDataLoader({ getBars, subscribeBar, unsubscribeBar })`.
2. **Chart's data loader was being torn down and rebuilt every 0.5s poll
   tick**, destroying the live callback registration before it could ever
   be used — confirmed via a live console capture literally showing
   `getBars → subscribeBar → unsubscribeBar` repeating every tick. Root
   cause: a React effect watched the candle array by unstable reference
   (Reflex creates a new array reference every render, even when content
   is unchanged). Fixed with an explicit `trading_panel_data_version`
   counter, incremented only on genuine full reloads.
3. **React StrictMode's intentional double-mount cycle permanently wiped
   the live-callback registry**, with no third mount ever occurring to
   re-subscribe — confirmed directly via `typeof
   window.QT19_LIVE_CALLBACKS[...]` printing `'undefined'` in console.
   Final fix: stopped relying on subscribe/unsubscribe lifecycle timing
   as the source of truth. Every poll tick now self-heals the
   registration if missing (`window.QT19_ensureLiveCallback`), making the
   live-push path resilient to StrictMode or any future remount race.

**Confirmed live and working by the user on 2026-09-05.**

### UI / layout
- Sidebar: real, visible collapse/expand toggle button added (state
  already existed but nothing called it); tooltips removed from nav
  links; converted to a genuine floating glass card (margin on all
  sides, full corner radius).
- Trading Panel: removed the old middle info row; folded "Display Last"
  input + "Available in QT19 Database" days into the header row; chart
  card now expands to fill all remaining page height (flex layout,
  `min_height="0"`) with no page-level scrollbar; added a live MM:SS
  countdown to next candle close.
- Settings page: fixed invisible tab/heading text in light theme
  (explicit `--qt19-text-primary` color); Settings sub-tab now persists.
- Hover-glow effect: multiple rounds of CSS specificity fixes attempted
  and superseded; ultimately removed entirely from the Trading Panel
  cards per final explicit user request (kept only on the sidebar).
- Console clutter from `poll_deep_history_cards` (was firing every 3s
  unconditionally): slowed to 10s and now self-stops when leaving the
  Settings tab.
