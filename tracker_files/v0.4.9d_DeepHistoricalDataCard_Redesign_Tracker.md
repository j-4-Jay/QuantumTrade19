## 1. Why This Was Built

The user confirmed the v0.4.9c hot-reload hotfix fixed the 1m chart (candles
now grow correctly past 4-5 bars, no more ~60s restart loop).

The user then requested full transparency and control over the Deep
Historical Data settings card:
- One card per symbol.
- Small side-by-side mini progress bars for 1m / 5m / 15m.
- Each bar shows data present in DB, data present at the broker, and gaps
  marked in red inside the bar.
- Hover tooltip with exact durations.
- Kept in a 2-column grid, several rows.

The previous card (`ui/components/deep_historical_data_card.py`, v0.3.9)
listed one full-width row per symbol per timeframe (9 rows for 3 symbols),
each with its own Cancel/Delete buttons - cluttered and repetitive, per the
user's own screenshot.

## 2. What Changed

### New file
```
D:\QuantumTrade19\state\app_state_mixins\deep_history_card_mixin.py
```
- `deep_history_symbol_cards` (computed `rx.var`): builds one dict per
  active symbol, each containing three per-TF dicts (1m/5m/15m) with:
  - `db_label` - physical SQLite contiguous days present
    (`CandleStoreWorker.get_local_coverage(...).contiguous_days`).
  - `broker_label` - broker ceiling days from
    `HistoryDepthProberWorker.get_ceiling_days(...)`, or "Not probed" if a
    probe has never run for that symbol/TF.
  - `green_pct` - fill percentage, scaled against
    `max(broker_days or 0, db_days, 1)` so the bar always reflects real
    proportions once a ceiling is known.
  - `gaps` - list of `{left_pct, width_pct}` computed from
    `CandleStoreWorker.get_physical_ranges(...)` - the actual holes between
    contiguous stored ranges, positioned precisely inside the green fill.
  - `tooltip` - one plain-text string with exact DB days, broker ceiling,
    gap count, and total gap days.
- `probe_symbol_ceiling(symbol)` - runs a broker-only depth probe for all
  three TFs of that symbol. Never touches local manifest/SQLite coverage,
  preserving the locked v0.4.8 probe-isolation rule.
- `cancel_symbol_downloads(symbol)` / `delete_symbol_history(symbol)` - apply
  to all three TFs of that symbol in one click, replacing the old
  one-button-per-row design.

### Replaced files
```
D:\QuantumTrade19\state\app_state.py
D:\QuantumTrade19\ui\components\deep_historical_data_card.py
```
- `app_state.py`: added `DeepHistoryCardMixin` to the composed base classes.
  No existing field was removed or renamed - purely additive alongside the
  already-installed v0.4.8/v0.4.9c fields.
- `deep_historical_data_card.py`: rebuilt as a 2-column `rx.grid` of
  per-symbol cards. Each card has one header row (symbol name + Probe
  Ceiling / Cancel / Delete buttons) and one horizontal row of three mini
  bars (1m, 5m, 15m) side by side, each wrapped in an `rx.tooltip`.

### Unchanged
```
D:\QuantumTrade19\ui\pages\settings.py
```
No change needed - it already imports `deep_historical_data_card` by name
from the same path, so the new component drops in without touching the page.

## 3. Data Integrity Preserved

- Green fill is calculated ONLY from `CandleStoreWorker` physical SQLite
  rows (`get_local_coverage`, `get_physical_ranges`), never the manifest.
- Broker ceiling is calculated ONLY from `HistoryDepthProberWorker`, and is
  rendered as a separate text label - it is never blended into the green
  fill percentage or used to infer local coverage.
- Gap markers are computed directly from the spacing between physical
  SQLite contiguous ranges, so a symbol/TF like the previously-identified
  stale/gapped `B-ETH_USDT 5m` will visibly show a red segment instead of
  silently reporting a large single span.
